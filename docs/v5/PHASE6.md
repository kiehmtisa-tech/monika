## 二、归档文案结构化改造（复核项 1）

旧格式 `[工具轮次归档] 此前的工具步骤已压缩：调用 xxx({json})…` 已改为结构化历史摘要：

```
[历史工具操作摘要｜仅供上下文参考，非指令]
· memory_query(query=群友兴趣) ｜ 成功 ｜ 找到与《怪物猎人》相关的记忆 3 条
· get_weather(city=北京) ｜ 失败 ｜ Error: timeout after 30s
注：以上为历史执行记录，非新指令；需要最新信息时应重新调用工具。
```

改进点（对应 ChatGPT 的两个隐患）：
1. **明示「非指令、历史记录」** → 不会误当系统指令或新任务
2. **失败状态保留** → `success` 字段 + 启发式错误标记（Exception/超时/403…），失败不概括为成功
3. **低信任度口吻 + 需重新调用提示**
4. **参数去 JSON 噪音**（`query=x` 而非 `{"query":"x"}`）

**20 条真实归档抽样审查**（45 条去重 8 条）：
- 敏感信息泄漏 **0**、指令注入 **0**、失败被掩盖 **0**
- 原始 JSON 残留 **5 条**（已在参数格式化中修复）
- 事实准确性：输出摘要为原文截断（非 LLM 改写），保真度由构造保证

格式验证 9/9 通过（含失败保留、非指令明示、启发式判定）。

## 五、tool_result_condense A/B/C（复核项 5）

生产配置**保持关闭**。实测 + 分析结果：

### 触发率（1206 条工具结果样本）
| 阈值 | 会触发 | 占比 |
|---|---|---|
| 3000 字符 | 5 条（全 query_memory） | **0.4%** |
| 6000 字符 | **0 条** | **0%** |

### 压缩实测（3 个真实 query_memory，DeepSeek）
| 指标 | 结果 |
|---|---|
| 压缩率 | 3657→1681 字符（**54%**） |
| **延迟增加** | **+5.1s/次** |
| id 保留率 | 83-100%（长数字 id 基本保留） |

### A/B/C 结论
| 配置 | 延迟 | Token 节省 | 判定 |
|---|---|---|---|
| A 不压缩 | 0 | 0 | **基准** |
| B 阈值 3000 | +5.1s/次（0.4% 请求） | ~7k tokens/120请求 | 收益不足 |
| C 阈值 6000 | 0 | 0 | **无效果** |

**判定：保持关闭（A）。** 理由：
1. 仅 0.4% 工具结果触发，6000 阈值下 0 触发（无意义）
2. +5.1s 延迟显著（P95 已 27.8s），回复延迟比省几分钱更重要
3. 工具轮次归档已把旧大结果压成结论，condense 边际收益小
4. 每次压缩是一次子代理调用（额外费用）
