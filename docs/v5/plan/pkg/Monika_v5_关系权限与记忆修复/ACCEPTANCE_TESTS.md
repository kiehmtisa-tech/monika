# Monika v5 验收测试

## A. 管理员识别与指令

1. QQ UID `100000001` 在群里真实 @Bot 并发出“本群禁止主动发图” → 识别为管理员禁止令。
2. 相同文本由其他 UID 发出 → 不得成为管理员规则。
3. 管理员没有真实 @Bot，只在正文写“莫妮卡” → 群聊中不触发管理员命令。
4. 管理员真实 @Bot 问“你今天怎么样？” → 普通聊天，不写入管理规则。
5. 管理员说“我觉得你可以少发图” → 作为建议，不自动变成禁止令。
6. 管理员说“本群禁止发图” → 只影响当前群。
7. 管理员说“所有群禁止发图” → 全局生效。
8. 其他用户试图撤销管理员禁止令 → 拒绝。
9. 管理员要求覆盖 Monika 核心身份或安全边界 → 拒绝。
10. 管理员关系身份不在群聊中被主动公开宣示。

## B. 关系模型

11. 高频刷屏不能无限增加熟悉度。
12. 双向交流与跨天互动可以形成定性熟悉程度。
13. 长期不互动不会删除重要共同经历。
14. 熟悉度不授予管理员权限。
15. 模型不能把单次友好对话推断为恋爱、忠诚或依赖。

## C. 记忆写回

16. 私聊新增 12 条消息后达到摘要阈值并写回。
17. 只有 4–11 条新增消息的低流量会话，在 idle flush 条件满足时能够收尾。
18. 空闲收尾不重复摘要已 checkpoint 的旧消息。
19. 只有寒暄和无信息量表情的会话不生成冗余摘要。
20. 重启后恢复 checkpoint，不重复写回同一窗口。

## D. Claim 分类与画像

21. “今天被领导批评” → episodic_event，不是 stable identity。
22. “今天已打完酒馆战棋” → episodic_event，不能作为长期兴趣结论。
23. “不会弹钢琴” → skill_state，有时间和来源，可被未来学习状态更新。
24. 多种措辞描述同一次酒馆战棋经历 → 语义去重。
25. “我长期喜欢 X，请记住” → preference/interest candidate，保留明确来源。
26. 单次明确自述可以 confidence 较高，但 stability 仍可以是 episodic。
27. 主体统一为 canonical QQ UID / bot ID，不依赖“他/目标人物/大肥鱼”等自由文本键。

## E. 检索与隔离

28. 旧空 vector space 不再被查询。
29. 新 space 的 paragraph/entity 向量数量和模型维度通过健康检查。
30. 关系查询可使用 BM25/图谱，不要求伪造关系向量。
31. A 群私聊内容不能出现在 B 群 Prompt。
32. 仅允许明确标记为跨群共享的低敏偏好跨群召回。
