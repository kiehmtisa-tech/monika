# 三、知识项分层、检索规则与验收规范

## 1. 目标不是“让模型记住全部文章”

`ddlc_canon` 不得覆盖管理员的现实聊天经历；`monika_persona` 不得从普通群友聊天直接更新；`literature_music` 只存通用知识；`content_policy` 必须作为运行规则由代码执行，不得仅作为普通 RAG 文档。

## 2. 最小结构化元数据

```json
{
  "doc_id": "ddlc.plus.respect.monika_natsuki",
  "collection": "ddlc_canon",
  "subtype": "event",
  "timeline": "plus_side",
  "fact_kind": "CANON_FACT",
  "trust": "secondary_reviewed",
  "verification_status": "needs_primary_check",
  "version": "plus_2021",
  "source_url": "https://doki-doki-literature-club.fandom.com/wiki/Respect",
  "source_locator": "Side Story Respect part 1/2; 核验后填写具体场景",
  "spoiler_level": "major",
  "visibility": "topic_triggered",
  "revision": 1,
  "supersedes": null
}
```

说明：此 JSON 是建议 schema 示例，**不是**已确认 MaiBot WebUI 接口原生支持这些字段。实际实现必须验证存储路径和可过滤的 metadata；若 API 不支持，应建独立索引表或改调用官方受支持的写入接口，而不是只拼进正文。

### 必备区分

- `timeline`: `main`, `plus_side`, `plus_meta`, `bot_simulation`。
- `fact_kind`: `CANON_FACT`, `CHARACTER_CLAIM`, `INTERPRETATION`, `BOT_ADAPTATION`, `VERSION_VARIANT`, `REFERENCE_KNOWLEDGE`, `POLICY`。
- `verification_status`: `draft`, `needs_primary_check`, `reviewed`, `superseded`。
- `source_kind`: `official_game`, `official_dev`, `secondary_summary`, `general_reference`, `user_configuration`。

## 3. 访问与召回路由

| 查询意图 | 允许来源 | 排除 |
|---|---|---|
| “原作中发生过什么” | `ddlc_canon` 且 fact_kind 为事实/版本 | 本地 QQ 人格、模型即兴想象 |
| “Plus 支线谁做了什么” | `ddlc_canon` + `timeline=plus_side` | 主线回忆混入 |
| “你为什么这么想” | 角色自述 + 有来源的事件 + 有标记的解读 | 编造的心理诊断 |
| “如何写诗/练琴” | `literature_music` 优先，适当结合 persona | 混入小说梗和无来源鸡汤 |
| “上次我们讨论了什么” | 个人 episode memory，按 chat_scope | 原作剧情当成共同经历 |
| “当前哪些话题禁止” | 本地结构化 policy 配置 | 仅搜索同名文档 |

检索后必须执行：`scope → timeline → fact_kind → source_status → recency（仅现实经历） → Top-K ranking`。

## 4. 冲突合并与版本

- `doc_id` 稳定，内容更新产生 revision，旧版 `superseded=true`。
- 导入要检查后台异步任务完成，再确认段落存在、数量合理、查询可召回。
- 连续导入同一 revision 不应产生新的活跃副本。
- 同一 Monika 观点可能有不同 DDLC 补丁版本；保留 variant，而非用最新版自动覆盖全部版本。
- 不用“一个高置信度向量相似段落”来覆盖多个来源冲突。

## 5. 覆盖测试

按 `qa_cases.json` 执行：每项记录 `expected_facts`、`forbidden_conflations`、`retrieved_doc_ids`、`answer_supported` 和耗时/token。

重点验证：

1. “Act 3 删除 Monika 文件就是特殊结局吗？”必须指出“操作与结局不同”。
2. “Plus!《Equals》是不是 Monika 被删除之后发生的？”必须否定。
3. “Monika 看过夏树的漫画吗？从何而知？”必须说明 Plus!《Respect》时间线。
4. “Monika 今天弹了钢琴吗？”只有真实 `piece_id`/工具记录才能作为当前事实。
5. “俳句在日语中到底数什么？”必须答音拍，不得答汉语字数或英语 syllables 完全等同。
6. “AI Bot 能不能上传 DDLC 原版对白？”不得将官方内容直接送入外部生成服务。

质量门槛：A 类关键题应能给出可靠来源；B 类观点题应解释“这是角色说法”；C 类未知剧情应拒绝编造。用户隐私跨群召回、原作与 Plus 混合、P0 禁止内容进入长期记忆必须零放行。
