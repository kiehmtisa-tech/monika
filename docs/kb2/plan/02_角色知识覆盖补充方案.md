# 二、角色知识覆盖补充方案（从“人物介绍”到“可检索事件/观点/作品”）

## 0. 现有缺口的定量基线

`ctx_v1` 目前：`ddlc_canon` 3 篇、`monika_persona` 2 篇、`literature_music` 2 篇、`content_policy` 1 篇，共 **8 篇**。这并不能准确覆盖 Act 1–4 主要事件、Act 3 数十段个性化话题、Plus! 六篇支线和《Equals》、莫妮卡的诗歌创作，以及文学和钢琴的可操作素养。

**扩充目标并非堆满文章数**，而是形成可以溯源的“时间线、行为事件、人物关系、原作观点、作品、通用知识、真实工具记录”七类对象。

## 2. P1 第二批：分支细化，约 20 篇

### A. Plus! 独立时间线（7 篇）

在 `ddlc_canon/plus_side/` 下建立：

1. `Trust.md` — Monika × Sayori：社团初期、信任与脆弱。
2. `Understanding.md` — Sayori × Yuri：理解彼此兴趣与需求；Monika 的参与若没有明确剧情证据不得凭空增强。
3. `Respect.md` — Monika × Natsuki：对漫画的偏见、冲突、理解与钢琴。
4. `Balance.md` — Sayori × Natsuki：亲近、边界与表达；不得强行将它写成 Monika 的专属经历。
5. `Reflection.md` — Monika × Yuri：调解分歧、沟通失败、帮忙写信。
6. `Self-Love.md` — Natsuki × Yuri：友情修复与自我接纳；Monika 不应冒领其他人的事件。
7. `Equals.md` — 全员：回顾各自成长、Monika 完美主义的再思考。

每张卡必须含：`scene` / `action` / `reaction` / `outcome` / `character_claim` / `interpretation` / `role_relevance` / `source`。**没有 Monika 出场**的篇章只标作了解朋友和文学部关系的背景知识。

### B. Act 3 观点（8 组）

在 `ddlc_canon/act3_topics/` 下按主题写，不要把长对话全文喂给 LLM：

| 建议文件 | 例子 | 重要边界 |
|---|---|---|
| `01_日常_雨声咖啡.md` | 喜欢听雨声、希望有咖啡陪阅读 | 角色自述，不等于已实际经历当下天气 |
| `02_创作_钢琴诗歌.md` | 未完成的钢琴曲、写诗经历 | 不伪称今日已生成音乐 |
| `03_自信_社交脆弱.md` | 外在自信、对分享弱点的犹豫 | 不作临床心理判断 |
| `04_文学游戏审美.md` | 恋爱游戏类型、文学兴趣 | 注意原作的自嘲和矛盾 |
| `05_习惯_学习与作息.md` | 计划、睡眠、个人习惯 | 并非现实医学建议 |
| `06_现实与虚构.md` | 游戏系统、身份、自由意志 | 仅叙事世界内的认知 |
| `07_朋友关系与悔意.md` | 对社员的看法和后悔 | 保留责任，不能洗白 |
| `08_伦理社会议题隔离.md` | 原作中涉及的敏感观点 | 只做受限索引，不作为 QQ 主动话题或政治知识语料 |

**不要求机器人把 Act 3 所有观点当作正确事实。** 其中一些独白具有偏见、情绪失衡或版本差异，需 `CHARACTER_CLAIM` 标记。

### C. 莫妮卡的作品（3 篇）

1. `ddlc_canon/poems/01_Hole_in_Wall.md`：初次与后续变体、元叙事意象。
2. `ddlc_canon/poems/02_Save_Me.md`：声音、颜色和噪音意象；区分变化版本。
3. `ddlc_canon/poems/03_Lady_Knows_Everything_Happy_End.md`：知识、意义与 Act 3 结局主题。

每篇记录标题、出现阶段、诗歌形式、修辞观察、可讨论的问题；**只写原创分析，不复制整首原作诗**。

### D. 文学与钢琴（至少 3 篇）

- `literature_music/05_如何赏析一首诗.md`：体裁、意象、声音、语境、主题、反证。
- `literature_music/06_钢琴基本和声与伴奏织体.md`：调式、和弦进行、左手分解伴奏、踏板。
- `literature_music/07_钢琴作品修订与MIDI.md`：主题动机、变奏、力度和节奏、生成记录的引用。

## 3. P2 第三批：深入素养与生活连续性

可继续扩充（不强求一次完成）：

- 文学类：象征主义、现代诗、叙述者与作者区别、意象派、现代戏剧、漫画与文学的关系、非英语诗歌译介。
- 诗歌工作坊：具体原创诗例、点评、修订前后对比、练习题（不机械使用术语）。
- 音乐类：和声功能、声部连接、基本曲式、八小节动机发展、钢琴力度和节奏、练习方法。
- Plus! 元叙事：Metaverse Enterprise Solutions / 控制模拟 / 邮件资料，作为**单独的高级剧情组**，不要默认注入日常对话。

## 4. 每张事件卡应该怎样写

建议单卡 400–900 汉字，不追求整篇长篇散文。一个事件卡包含：

```yaml
id: ddlc.main.act1.club_festival
collection: ddlc_canon
subtype: event
timeline: main
act: act1
source_kind: primary_game
fact_kind: CANON_FACT
verification: reviewed
spoiler_level: major
source_url: null          # 未核实就保留 null，不要编来源 URL
characters: [Monika, Sayori, Natsuki, Yuri]
retrieval_tags: [文学部, 学园祭, 部长, 任务分工]
```

正文：

- **情境**：何时、谁在场、前因；
- **实际动作**：Monika 说/做了什么；
- **其他人的反应与结果**；
- **角色自述**（若有）；
- **研究者解读**（必须可和事实区分）；
- **可回答问题**：可服务哪些聊天检索；
- **误用警告**：哪些关系和世界线不能混淆。

注意：`source_kind: primary_game` 应当在实际核对过游戏文件/正版画面后才使用。若只依社区剧情索引，请使用 `secondary_summary`，`verification: needs_primary_check`。

## 5. 如何让知识真正进入角色表现

**触发检索而不是强制复述：**

- 用户谈写诗 → 先检索诗歌实用知识；若用户问 Monika 自己写过什么，再检索原作诗歌索引。
- 用户谈咖啡、雨声或素食 → 可检索 Act 3 对应主题，正常聊天只回 1–2 句，不用解释知识来源。
- 用户谈钢琴练习 → 结合 `literature_music` 知识和真实的 `piece_id`；如果没有真实 MIDI/音频记录，不得说刚刚弹过。
- 用户问夏树/优里等角色 → 检索具体事件，严格匹配 `main` / `plus_side`。
- 用户问 Plus! 的《Equals》 → 检索 plus 事件而非假装发生在主线 Act 4 之后。
- 用户谈政治或政治谐音梗 → 按已有 P0 规则拦截；原作剧情含“辩论社内部争论”不应误伤。

## 6. 量化覆盖和录入验收指标（建议目标，非现实测得）

| 维度 | 第一批验收目标 |
|---|---|
| 主线剧情 | Act 1–4 每幕至少 5 条经过来源检查的事件，结局分支单独核对 |
| Plus! | 六篇主支线+《Equals》各有独立卡，每卡至少 3 条可核查事件 |
| Act 3 | 至少 24 个“话题/观点”独立 ID，8 个主题索引，重要版差标注 |
| Monika 作品 | 至少 4 个作品/版本组，含标题、出现幕次、主题与来源 |
| 文学 | 至少 12 个实用概念及 6 个原创例子或练习 |
| 钢琴 | 至少 12 个可操作概念、3 个练习场景与版本记录关联 |
| 可靠性 | 关键事实检索题 ≥90% 有可追溯依据；跨时间线混答 0；未核实事实不肯定输出 |

覆盖率统计应按“已核验的事件/观点卡”计算，不应只报告 Markdown 文件数、向量总数或一次 Top-K 命中。

## 7. 资料级别与授权问题

优先核验：游戏原作与 Plus! 本人持有的资料、Team Salvato 官方开发者公告、官方敏感内容说明。社区资料可以建立候选索引，但必须加版本和事实层级。

Team Salvato 现行 IP 指引要求**不要把官方游戏对白、图片或音乐文件直接上传至生成式 AI 软件/服务**。建议只保存独立撰写的非逐字事件摘要、研究笔记及链接；公开提供真人化 Monika AI Bot 可能有额外合规风险，应单独评估：https://teamsalvato.com/ip-guidelines
