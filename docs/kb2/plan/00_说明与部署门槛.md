# Monika 知识库 v2 · 审核与扩充规划

## 审核基线

- 原始来源：`ctx_v1.zip` 中 `knowledge/` 的 8 篇 Markdown。
- 同时使用上一轮审核报告和旧修订候选作为差异参考；**本包候选修订文本不是运行中数据库状态**。
- 事实核验：Team Salvato 官方作品介绍、官方 DDLC Plus! 开发者说明、官方内容警示，文学/乐理权威参考；原作话题索引使用可复核的二级资料，尚未完成逐句版本对照。

## 最重要的三条边界

1. `ddlc_canon`：记录原作**明确发生**的事件；角色主观说法单独标注；本篇、Plus! 支线和隐藏元叙事不得混为同一个人的连续真实经历。
2. `monika_persona`：记录你的 Bot 改编设定；禁止把“QQ群管理员身份”“回复 4–25 字”“大肥鱼昵称”冒充原作事实。
3. `literature_music`：记录通用知识；和原作 Monika 个人兴趣分开。懂乐理不等于原作角色实际拥有该知识或曾弹过某作品。

## 来源优先级

`游戏内可定位的事件或官方明确说明 > 官方说明书/网站 > 经交叉核对的社区剧情索引 > 第三方评论 > 作者推论`。

**重要：** Team Salvato 的 2026-04-29 IP 指引禁止将官方游戏资产（明确包括游戏对白）上传至生成式 AI 软件或服务，并对使用生成式 AI 描绘角色的同人游戏施加限制。本包只使用原创中文转述、事实索引和资料链接，不附游戏台词全文、原始贴图或音轨；对公开提供角色 Bot 的合规性，应单独评估，不能把本包视为获得官方授权。

官方指引：https://teamsalvato.com/ip-guidelines

## 交付结构

- `01_事实准确性修订方案.md`：逐文件定位、建议替换与验证依据。
- `02_角色知识覆盖补充方案.md`：按照原作事件、Act 3 话题、Plus!、文学与钢琴拓展的优先级与文档目录。
- `03_来源分层与检索验收规范.md`：事实标签、检索与版本管理、避免污染的实施方案。
- `04_OpenClaw_执行任务.md`：可直接复制给 OpenClaw 的分阶段执行任务。
- `候选修订版_现有8篇/`：8 篇现有文档的**候选修订**，供 diff 审核，并未部署。
- `新增内容样本/`：若干经过公开资料交叉核验的索引样本，不是完整剧情知识库。
- `qa_cases.json`：建议的对照测试集合；测试结果需在现场跑。

## 实施顺序

P0：备份 → 修订事实 → 补来源字段 → 逐文档审批与版本化导入 → 查询回归。

P1：建立 Act 1–4、Act 3、六篇支线+Equals 的事件/观点/作品卡。

P2：文学、写作、钢琴练习与原创音乐工具的知识扩展。

## 不得将“目录”当作检索隔离

原版 `knowledge.py` 向 WebUI 导入 API 提交 `{content, name, input_mode}`，`collection`/`trust` 在正文前缀里，并不能证明物理/逻辑隔离已执行。使用新目录前，先确认存储层的结构化元信息、检索时的 scope/trust 过滤和同名版本去重。否则运行时仍可能混淆 `canon` / `persona` / `policy`。
