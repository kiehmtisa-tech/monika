# OpenClaw 任务：Monika KB v2 原作纠错与覆盖扩充

请先读取本目录 `00_说明与部署门槛.md`、`01_事实准确性修订方案.md`、`02_角色知识覆盖补充方案.md` 和 `03_来源分层与检索验收规范.md`，并对照现有生产 `ctx_v1/knowledge`。**不要直接覆盖线上知识库，也不要把已有聊天和人格数据重新导入成原作事实。**

## Phase 0 只读核查

1. 输出生产知识库当前 8 篇的 SHA-256、版本、source_id、分段及索引状态；比较本地候选修订差异。
2. 核查 `knowledge.py` 运行时导入接口是否具备真正的 `collection/trust/source_type` 结构化 metadata；若不支持，先提出替代路由方案，不能称作四个物理隔离 collection。
3. 检查官方 DDLC IP 指引：禁止将官方台词/音乐/图片文件上传生成式 AI 服务；确认扩充仅采用独立撰写的剧情/观点摘要与来源链接。

## Phase 1 原作事实修订（第一优先）

1. 对 `候选修订版_现有8篇` 执行逐文件 diff；优先核对 MC/Player、Act 3/结局、Plus 侧故事、俳句、简谱/固定音名。
2. 为每个真实剧情陈述补可核查的 source URL 或游戏幕次/场景定位；来源不足标记 `needs_primary_check`。
3. 把 Character Claim / Interpretation / Bot Adaptation 从“原作事实”拆分；不把旧人设 prompt 当作原始事实证据。
4. 人工批准后，使用版本化 ingest；核对异步任务完成、source_id 与检索命中。不要只看 HTTP 200。

## Phase 2 新增角色剧情索引

按 `02_角色知识覆盖补充方案.md` 的 P0 顺序先补主线 Act 1–4、Act 3 主题、Plus! 六篇+《Equals》和 Monika 作品；每条包含实际动作、反应、来源、世界线和需要避免的错误解读。

禁止将 Plus! 的 Side Stories 与 Act 4 混为单一时间线。对 Monika 未亲自参与的支线标记“其他社员的经历”，不要给她编造第一人称回忆。

## Phase 3 文学与音乐

采用权威来源添加诗歌形式、诗歌赏析、原创练习题和钢琴教学卡。文学知识的权威不意味着 Monika 在原作里已经读过或弹过所有书曲。

音乐作品记录单独链接真实 MIDI/音频工具执行 ID，不得写“已经弹过”而无工具凭证。

## Phase 4 验收

- 运行 `qa_cases.json`，按 **原作准确率 / 时间线混合率 / 事实来源完整率 / 角色归属率 / 入库幂等 / 平台隐私隔离 / 查询开销** 逐项报告。
- 用 26 项旧基准 + 新基准构成修订前后 A/B；保留原始模型输入、检索 doc_id、结论及错误复现，不要仅提供“问了一次正确”的截图。
- 不得改动现有 QQ 管理员权限、内容黑名单与 A-Memorix 生产记忆；如需改动，应单独进入迁移任务并留下回滚方案。

## 交付

- 逐文件 diff、审稿状态、引用来源、导入任务 ID、当前唯一活跃 revision。
- 未完成、未核实、存在版本差异的条目列表。
- 各类别覆盖数（**已核实事件数**，不是单纯文件数）。
- 可复现回归测试、资源消耗、回滚说明。
