**结论（含历史证据）**：
- 新会话下 60/75 差异不显著（窗口只在历史 >60 条时才开始截断）。
- **v5 已做过 75→40 实验且无效并还原**：窗口按"消息条数"计，为保持工具调用轮完整会溢出；
  构成分析显示膨胀主源是**历史工具调用链（占输入 22.1%）**而非普通聊天条数。
- **建议维持 75**；真正的杠杆是"历史工具调用裁剪/tool_result_condense"（已列入待办），
  而不是把 150 调小或把 60 再调。审查建议的"近期原始 40-60 条 + 摘要 5-8 条"分层架构
  需要改上下文组装代码（镜像内），属中期项。

### 3.3 chat_summary 阈值写回 bug（A5）——根因与修复

- 复现 3 次的"12→72→144"漂移根因：**[a_memorix.*] 配置的权威模型在内存**，
  runtime auto-save 会把旧内存快照写回文件；直接编辑 TOML 不更新内存模型。
- **修复**：`PUT /api/webui/memory/config`（body `{"config": 全量配置}}`）设置 12/12，
  内存与文件同步生效、20s 盯盘无回写。当前生效值：**threshold=12 / context_length=12**。
- **操作规程**：改 [a_memorix.*] 一律走 memory config API；改其他 section 才用文件编辑+热重载。
